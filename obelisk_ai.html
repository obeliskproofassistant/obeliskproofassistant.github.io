Obelisk Architecture, Formal Systems & Developer Guide

MKTD stands for Morse–Kelley class theory + Tarski (Grothendieck) universes + Dunaev tagged pairs. Obelisk develops this mathematical domain in two distinct formal systems implemented in Standard ML: MKTD1-system (classical sequent calculus) and MKTD2-system (classical dependent type theory). They differ in their primitive judgment and are never merged.

This page is a factual architectural reference for developers and automated agents. Theorem counts, proof statuses, and axiom footprints are never maintained by hand on static pages; consult the SML-generated catalogs and JSON reports linked below.

2. Trusted Kernels, Separate Checkers, Previews & Architectural Boundaries

Not every executable artifact in the workspace is part of the trusted LCF kernel. When inspecting or extending Obelisk, keep the following boundaries strictly separate:

Trusted MKTD1 Kernel (program/newchecker/)

structure ThmWithPrf :> THM_KERNEL keeps Thm abstract. ThmWithPrf.cheat raises an exception, and derive, check, slow_check, and checkPlus all reject PCheat_prf (as well as legacy PS1_prf and PHenkin_prf). A closedness gate rejects theorem statements with free class variables. Entry 3.69 (v_universe_thm, v_universe_thm_proof) is proved from standard axioms without using the backup VUniverseAx.

Trusted MKTD2 Checker (dependent_typechecker.ML)

program/dependent_typechecker.ML and program/dependent_eval.ML check every record in program/verified_theorems.ML at load time and export nbg_library.html via program/nbg_html_generator.ML. The transitive axiom footprint of every MKTD2 record is generated by tools/mktd2_axiom_footprint.ML into docs/MKTD2_AXIOM_FOOTPRINT.txt.

Separate Surface Checker (program/nbg_compiler.ML)

NBGCompiler (NBGCompiler.typeCheck) is a second, independent MKTD2-style typechecker for the .nbg surface language (checking surface scripts such as dunaev_pair_injective and dunaev_cartesian_elim). Known architectural debt (GitLab #8092): NBGCompiler is not yet cross-checked against DependentTypeChecker.

Statement Bridge & Untrusted Previews

program/variant_bridge.ML translates statement representations between MKTD1 and MKTD2 and checks consistency; it does not transfer proofs. The browser Web REPL (js/obelisk_engine.js) is a client-side JavaScript preview, not the Standard ML kernel. Similarly, obelisk_kernel.py is a Python teaching model and program/lcf.ML is a standalone experiment.

3. Core Mathematical & Syntactic Distinctions

3.1 Four Theories (datatype Theory_p, program/types/typetheory.ML) & Stratification

Constructor Symbol Role in MKTD1
IpTau 𝘛 The base theory: consistent and recursively axiomatizable.
IpFau 𝘍 A complete (Henkin / Lindenbaum) extension of 𝘛; not recursively axiomatizable. Most kernel axioms and rules are stated in 𝘍.
IpEau 𝘌 An unspecified elementary metatheory 𝘌 ∈ {IΣ₁, PA, 𝘛, NBG, MK} strong enough for the Hilbert–Bernays–Löb derivability conditions (so not Robinson's Q).
IpWau 𝘞 An arbitrary MKTD1 theory parameter.
  • Reflection rules: Omnis infers (𝘍, [] ⊢ Holds(W, Γ ⊢ φ)) from a derivation of (W, Γ ⊢ φ); Credo infers S from (𝘍, [] ⊢ Holds(S)).
  • Object-level stratification (Fm₀): Class comprehension (PComprAx_prf) and opaque kernel definitions (KernelDefinitions :> KERNEL_DEFINITIONS yielding PKernelDef_prf (name, params)) accept only object-level formulas satisfying KernelDefinitions.is_object_level_fm0. This rejects reflection and syntax-inspection constructors (TpHolds, TpFFI, TpIFV, TpCtxIFV, EEval, EAnti, CpFV, CpCtxFV, CpEnc), preventing diagonalisation over (𝘍, [] ⊢ ·) and blocking both Tarski liar sentences and Löb fixed points.
  • Fixed axiom forms: EpsIndAx K is the ∈-induction principle (𝒫(K) ⊆ K) —→ (V ⊆ K) in 𝘍 with empty context. Additional primitives in MKTD1 are CardLessOrderAx (|A| ≺ |B| iff A ≺ B) and IfTrueAx / IfFalseAx for IF φ THEN A ELSE B FI.

3.2 Syntax vs. Semantics, Variables, Binders & Metalevels

  • Semantic objects vs. expressions: Semantic objects (Class, Bool, Type) are model-level values and are neither free nor bound. Free variables, substitution, and hygiene predicates exist only for syntactic expressions (Class.Expression, Truth.Expression = Fm, Ctx.Expression, Stmt.Expression). Say "free class variable x", never "free class x".
  • Terms denote classes; types are conglomerates: An object term denotes a class. A type is a predicate on classes (Class → Bool), with default type Class. Class comprehension {x : Class | φ(x)} always binds a Class variable, never Set. Sethood is a predicate: (x set) ⟺ ∃u (x ∈ u).
  • Typing : is not membership ∈: (x : Class) is a typing judgment; (x ∈ Y) is an object formula about two classes.
  • Kinds of variables: class variable (x : Class), variable-name metavariable (x : Variable), class-expression metavariable (t : Class.Expression), formula metavariable (𝛗 : Fm, Greek letters 𝛂 𝛃 𝛄 𝛗 𝛙 𝛘), type metavariable (A : Type), and context metavariable (Γ : Ctx).
  • Binder vs. occurrence: The variable written at a binding site (after ∀ ∃ ∃! ι τ ε λ Π Σ, in {x | …}, or in let x = …) is a binder; only uses inside the scope are bound or free occurrences.
  • Metalevel 0 vs. Metalevel +1: Object formulas live at metalevel 0 (Fm₀). Side conditions and syntactic judgments live at metalevel +1: Fm.FFI((t:X.Expression), x, (𝛗:Fm)), NFV(X, x, (𝛃:Fm)), Fm.IFV(x, 𝛙), (t : X), (x : Variable), and Holds(…). Side conditions are printed directly without antiquotation brackets ⟦…⟧, and free-variable occurrence uses the binary predicate Fm.IFV(x, 𝛙) rather than set membership. Substitution always takes arguments in the order (what, instead of what, where): FFI(t, x, 𝛗), SubstVar(t, x, v).

3.3 Dunaev Tagged Pairs vs. Set-Only Kuratowski Pairs

Dunaev Tagged Pair (A, B)

Defined for arbitrary classes (including proper classes) in entry 3.76 (DefDunaevOrderedPair, program/types/universe_definitions.ML) as: (A, B) = mark(A, 1) ∪ mark(B, 2) with tags 1 = {∅} and 2 = {∅, {∅}}. Projections and injectivity for arbitrary classes are proved in thm_3_77_dunaev_pr1_sub, thm_3_78_dunaev_pr2_sub, thm_dunaev_opair_injective, and proofDunaevPairInjectivity (and in .nbg surface syntax as [A, B]_D in dunaev_pair_injective and dunaev_cartesian_elim).

Kuratowski Pair opairK(a, b) & Class Equality

The Kuratowski pair opairK(a, b) = {{a}, {a, b}} is meaningful only for sets; it collapses on proper classes because proper classes cannot be elements. The two pair constructions are distinct symbols and are never identified. Class equality is extensional with elements on the right: A = B ⟺ ∀Y (Y ∈ A ⟺ Y ∈ B) for all classes.

3.4 The Four Arrows & 3-Tier SML Constructor Naming

Symbol ASCII Meaning
—→ --> Object-level material implication connective on formulas (TpImpl in MKTD1).
→ -> Function type in MKTD2 dependent type theory.
⟹ ==> Meta-level constructor arrow in formation rules (paired with ∷ and ↦).
f : A → B Set-function shorthand: f function ∧ Dom(f) = A ∧ f[A] ⊆ B.

SML 3-tier constructor naming (FACTBOOK.md §9): For any syntactic stem <Stem> (such as EmptySet or In): (1) pattern constructors Cp<Stem> in Class_p and Tp<Stem> in Truth_p; (2) head-injected constructors CH<Stem> = HC o Cp<Stem> and HP<Stem> = HP o Tp<Stem>; (3) full expressions C<Stem>, EP<Stem> = EInject o HP<Stem>, and F<Stem> = Fm_id o EP<Stem> (with typed aliases such as CEmptySet_Class_Expression and FIn_Class_Class_Truth_Expression). For how the 7 mathematical points of view relate across MKTD1 and MKTD2, see Points of View.

4. Surface .nbg Type-Checking Walkthrough (NBGCompiler.typeCheck)

In the .nbg surface language (checked by NBGCompiler.typeCheck in program/nbg_compiler.ML and previewed interactively in Web REPL), a formula declaration defines a proposition type (even an uninhabited one such as False_RussellIsSet), whereas a theorem declaration supplies a proof term whose synthesized type must convert to the target formula: 

formula False_RussellIsSet = Set({ x | ((x in x) -> Bot) });
theorem thm_russell_not_set : (Set(R) -> Bot) = fn (hSet : Set(R)) => ...;

Context Δ (Variable Signature)

Maps free class variables to sorts: Δ = {x : Class, y : Class, ...}. Governs universal binder typing: ELam(x, sort, body) : ∀(x:sort) T.

Context Γ (Proof Hypotheses)

Maps hypothesis labels to proposition types: Γ = {h₁ : A, h₂ : B, ...}. Governs implication introduction and elimination: EFn(h, A, body) : A → B.

Set(X) vs isSet(X)

Surface .nbg syntax writes Set(X) as an ASCII shorthand for the sethood predicate isSet(X) ⟺ ∃y (X ∈ y), distinct from the conglomerate sort Class.

Typing Rules for Proof-Term Constructors

ELam (universal abstraction over Δ), EFn (implication abstraction over Γ), ECompr (comprehension schema compr(x.φ, z)), EFst and ESnd (conjunction/product projections), and EApp (modus ponens / function application).

Worked Example 1: Empty Class Has No Elements

empty_class_no_elements : ∀(z : Class) ((z ∈ {x | ⊥}) → ⊥) =
  Lam (z:Class) => fn (hIn : (z in {x | Bot})) => snd(fst(compr(x. Bot, z)) hIn)

ELam introduces z : Class into Δ; EFn introduces hIn : (z ∈ {x | ⊥}) into Γ; ECompr synthesizes the comprehension equivalence; EFst extracts the forward implication; EApp applies it to hIn yielding isSet(z) ∧ ⊥; and ESnd projects ⊥.

Worked Example 2: Binary Intersection Left Inclusion (without ⊥)

thm_inter_subset_left : ∀(A:Class) ∀(B:Class) ∀(x:Class) ((x ∈ (A ∩ B)) → x ∈ A) =
  Lam (A:Class) => Lam (B:Class) => Lam (x:Class) => fn (hIn : (x in (A /\ B))) => fst(hIn)

Three ELam abstractions bind A, B, x : Class in Δ, EFn assumes hIn : (x ∈ (A ∩ B)) in Γ, and EFst (fst(hIn)) projects the left conjunct x ∈ A directly under definition unfolding of binary intersection (DefBinaryIntersection, 3.41).
