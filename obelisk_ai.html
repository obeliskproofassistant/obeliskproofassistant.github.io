Two Provers · Two Systems

Two Systems: The Syntactic Prover & The Type-Theoretic Prover

Two Sides of Curry–Howard: Syntactic Logic vs. Type Semantics

Prover 1 · Syntactic System (Formulas & Proofs)

Formulated from the syntactical perspective of proof theory (the left side of the Curry–Howard correspondence). It speaks in terms of formulas, variables, terms, sequents (Γ ⊢ φ), and explicit derivation trees, checked by an ultra-small trusted LCF kernel in Standard ML (newchecker.ML, foundations.ML) with 106 verified entries.

Prover 2 · Type-Theoretic System (Types & Programs)

Formulated from the semantical perspective of types (the right side of the Curry–Howard correspondence). It speaks in terms of types, proof terms / programs, and typing judgments (p : A). Proof terms are constructive λ-terms verified by NBGCompiler.typeCheck (nbg_compiler.ML), verifying all 100 machine-checked standard library records in generated/nbg_library.html.

Why the Two Theories Differ

While guided by the Curry–Howard correspondence, the two systems are not merely a cosmetic renaming of each other. Their underlying mathematical theories differ: Prover 1 is a classical first-order sequent calculus over Morse–Kelley class theory, whereas Prover 2 is a constructive dependent type theory with computational conversion (αβδ). Each prover explores the foundational domain through its own distinct logical nature.

Dunaev Tagged Ordered Pairs

Standard Kuratowski pairs \((\langle A, B angle = \{\{A\}, \{A, B\}\})\) fail for proper classes because proper classes cannot be elements of sets. Both provers solve this via Dunaev Tagged Pairs \(([A, B]_D = (\mathrm{mark}(A, 1) \cup \mathrm{mark}(B, 2)))\), enabling arbitrary proper classes to form pairs and lists without universe elevation, with machine-checked projection injectivity (proofDunaevPairInjectivity).

Compiler Architecture · Standard ML & CakeML

        
Morse-Kelley Propositions-as-Types: Compiling to Check, Not Execute

      


      

        

          In Obelisk, we establish a strict 1-to-1 Curry–Howard correspondence between mathematical theorems of Morse-Kelley (MK) Impredicative Class Theory and compiler types.
          Because MK allows quantification over proper classes in class comprehension, it provides the full expressive strength of higher-order logic over sets, while the compiler operates under the foundational principle: it compiles not to generate runtime executable bytecode, but strictly to verify whether the proof expression type-checks.
        


        

          

            
Standard ML Native Kernel

            

              Eliminates dynamically typed languages like Python from the trusted kernel. Fully written in Standard ML 97 targeting the CakeML verified compiler for machine-code assurance down to silicon.
            

          

          

            
Theorems as Types (1-to-1)

            

              Every mathematical theorem (Modus Ponens, Conjunction Symmetry, Russell Paradox Refutation) corresponds to a unique type. Proof terms are formal witnesses checked by the SML type checker.
            

          

          

            
Dunaev Tagged Ordered Pairs

            

              Replaces Kuratowski pairs (which collapse on proper classes) with [A, B]_D tagged pairs that preserve well-foundedness and algebraic projections without universe elevation.
            

          

          

            
Lightweight Offline Proof Checking (<50 MB RAM)

            

              Validates all 106 verified kernel catalog entries (1.01–5.02 in Variant 1) and 100 machine-checked theorem records (77 derived, 16 definitional, 7 axiomatic in Variant 2) in <50 MB RAM under Poly/ML & CakeML or zero-install browser JS, contrasting with multi-gigabyte JVM/LSP heaps.

                Notation Disambiguation & Kernel Contexts (Δ vs Γ)
                See docs/glossary.md • symbols.html
            

            

                

                    Context Δ (Variable Signature):

                    Maps free class/set variables to sorts: Δ = {x : Class, y : Class, ...}.

                    Governs binder typing: ELam(x, sort, body) : ∀(x:sort) T.
                

                

                    Context Γ (Proof Hypotheses):

                    Maps hypothesis labels to proposition types: Γ = {h₁ : A, h₂ : B, ...}.

                    Governs implication intro/elim: EFn(h, A, body) : A → B.
                

                

                    Set(X) vs isSet(X):

                    Surface .nbg syntax writes Set(X) as a concise ASCII synonym for the formal catalog predicate isSet(X) ≡ ∃y (X ∈ y). Never confused with the type Class.
                

                

                    Soundness of Tagged Class Structures:

                    • Dunaev Pair (⟨A, B⟩D): Tagged ordered pair (mark(A, 1) ∪ mark(B, 2)) sound for arbitrary proper classes (unlike Kuratowski pairs {{a}, {a, b}} which require a, b ∈ V). Source: foundations.ML (entries 3.76–3.78).

                    • Dunaev Class-List: Iterated tagged pairing [X₁, ..., X_n] with empty list [] (entry 3.39: DefClassLists) representing class tuples without conglomerates.
                

            

        


        
        

            

                Worked Example 1 · Proof-Term Walkthrough (with Constructor Typing Rules & Derived Types):

                empty_class_no_elements : ∀(z : Class) ((z ∈ {x | ⊥}) → ⊥) = Lam (z:Class) => fn (hIn : (z in {x | Bot})) => snd(fst(compr(x. Bot, z)) hIn)
            

            

                

                    Constructor Typing Rule · ELam (Universal Abstraction)

                    Rule: (Δ, z:Class; Γ ⊢ e : T) / (Δ; Γ ⊢ Lam (z:Class) => e : ∀(z:Class) T)

                    Introduces variable z : Class into variable signature Δ.
                

                

                    Constructor Typing Rule · EFn (Implication Abstraction)

                    Rule: (Δ; Γ, h:A ⊢ e : B) / (Δ; Γ ⊢ fn (h:A) => e : A → B)

                    Adds antecedent hypothesis hIn : (z ∈ {x | ⊥}) to proof context Γ.
                

                

                    Constructor Typing Rule · ECompr (Comprehension Schema)

                    Rule: compr(x.φ, z) : (z ∈ {x | φ}) ⇔ (isSet(z) ∧ φ[z])

                    Synthesizes bi-implication (z ∈ {x | ⊥}) ⇔ (isSet(z) ∧ ⊥).
                

                

                    Constructor Typing Rule · EFst (Product Left Projection)

                    Rule: (Δ; Γ ⊢ e : A ∧ B) / (Δ; Γ ⊢ fst(e) : A)

                    Bi-implication P ⇔ Q is product (P → Q) × (Q → P). fst(compr(...)) yields forward direction (z ∈ {x | ⊥}) → (isSet(z) ∧ ⊥).
                

                

                    Constructor Typing Rule · EApp (Function Application)

                    Rule: (Δ; Γ ⊢ e₁:A→B, e₂:A) / (Δ; Γ ⊢ e₁ e₂ : B)

                    Applies forward implication to hypothesis hIn: fst(compr(x. Bot, z)) hIn : isSet(z) ∧ ⊥.
                

                

                    Constructor Typing Rule · ESnd (Product Right Projection)

                    Rule: (Δ; Γ ⊢ e : A ∧ B) / (Δ; Γ ⊢ snd(e) : B)

                    Projects second component: snd(fst(compr(x. Bot, z)) hIn) : ⊥. Closed derivation tree verified!
                

            

        


        

            

                Worked Example 2 · Non-Absurdity Proof-Term Walkthrough (without ⊥):

                thm_inter_subset_left : ∀(A:Class) ∀(B:Class) ∀(x:Class) ((x ∈ (A ∩ B)) → x ∈ A) = Lam (A:Class) => Lam (B:Class) => Lam (x:Class) => fn (hIn : (x in (A /\ B))) => fst(hIn)
            

            

                

                    Constructor Typing Rule · ELam × 3 (Iterated Universal Abstraction)

                    Introduces variables A, B, x : Class into variable signature Δ.

                    Context: Δ = {A:Class, B:Class, x:Class}; Γ = ∅.
                

                

                    Constructor Typing Rule · EFn (Implication Abstraction)

                    Assumes hypothesis hIn : (x ∈ (A ∩ B)) into proof context Γ.

                    By intersection definition DefBinaryIntersection (3.41), x ∈ (A ∩ B) ≡ (x ∈ A ∧ x ∈ B).
                

                

                    Constructor Typing Rule · EFst (Conjunction Left Projection)

                    Rule: fst(hIn) : x ∈ A.

                    Completes proof of x ∈ A constructively without invoking falsum (⊥) or contradiction!
