MKTD

The mathematical subject of Obelisk: Morse–Kelley class theory together with Tarski's axiom of universes, with Dunaev pairs as ordered pairs. The letters stand for Morse–Kelley, Tarski, Dunaev.

Obelisk develops MKTD in two separate formal systems, MKTD1 and MKTD2.

Morse–Kelley class theory (MK)

A theory whose objects are classes. Its characteristic axiom is class comprehension: for every formula φ(x) the class {x | φ(x)} exists; its elements are exactly the sets x with φ(x). In MK the formula φ may quantify over all classes, not only over sets. Compare NBG (von Neumann–Bernays–Gödel class theory).

Reference: Wikipedia: Morse–Kelley set theory.

NBG (von Neumann–Bernays–Gödel class theory)

A class theory like MK, except that class comprehension {x | φ(x)} is allowed only when every quantifier in φ ranges over sets. Every theorem of NBG is a theorem of MK.

Reference: Wikipedia: NBG set theory.

Class

The only kind of object in MKTD. Every object is a class, and some classes are sets. The basic relation is membership, a ∈ A, read "a is an element of A".

Set

A Class that is an element of some class: X is a set if and only if X ∈ Y for some class Y (definition).

Proper class

A Class that is not a Set (definition). Examples: V, the class of all sets, and On, the class of all ordinals. A proper class is not an element of any class.

Universe

A class U with these properties (definition): ω ∈ U; every element of U is a subclass of U (transitive); every subclass of an element of U is an element of U (hereditary); the power set of an element of U is an element of U (powerful); for a subclass B of U, B is an element of U exactly when B is strictly smaller than U (tight); and with two elements a, b of U also {a, b} is an element of U (pairful).

The textbook notion is the Grothendieck universe: Wikipedia: Grothendieck universe.

Tarski's axiom

The axiom that every Set is an element of some Universe that is itself a set (axiom).

Dunaev pair

The ordered pair of MKTD, written (A, B) (definition). Write 1 = {∅} and 2 = {∅, {∅}}. Every element a of A is replaced by the set {{{{a}}}, 1}, and every element b of B by {{{{b}}}, 2}; (A, B) is the class of all these sets together with the two markers {∅, 1} and {∅, 2}.

Only the elements of A and B are used, never A and B themselves, so A and B may be proper classes. Proved in Obelisk: (A, B) = (C, D) implies A = C and B = D.

Compare Kuratowski pair.

Class list

A finite list of classes built from tagged copies, so that its members may be proper classes (definition uses only the lists below). With mark(A, n) = {{∅, n}} ∪ { {{{{a}}}, n} | a ∈ A }: [] = ∅, [A] = mark(A, 1), and [A, B] = mark(A, 1) ∪ mark(B, 2). The two-element list [A, B] is the Dunaev pair (A, B).

Context

The list of hypotheses of a statement. In MKTD1 a context Γ is a finite list of formulas [φ₁, …, φₙ], and (T, Γ ⊢ φ) says that φ follows from them. In MKTD2 a context lists variables and hypotheses together with their types.

Kuratowski pair

The usual ordered pair of sets, {{a, a}, {a, b}} (definition). It requires a and b to be sets, because a proper class cannot be an element of {a, a}. MKTD uses Dunaev pairs instead.

Formal system

A precise description of which expressions are statements and which statements are derivable. In Obelisk a formal system consists of a Framework and a list of axioms.

Framework

The logical part of a formal system: the language, the form of its judgments and the rules of logic, without the axioms of class theory. Obelisk has two:

MKTD1-framework: a classical sequent calculus. Its judgments have the form (T, Γ ⊢ φ), read "in the theory T, the formula φ follows from the hypotheses Γ". The language can quote its own formulas (Quotation and antiquotation).

MKTD2-framework: a dependent type theory. Its judgments have the form p : A, read "p is a proof of the proposition A" (Propositions as types).

Axiom

A statement that is accepted without proof. In Obelisk every axiom is built into a Kernel; its entry has a status that begins with "Postulated" (Status of an entry).

MKTD1

The first of Obelisk's two formal systems for MKTD. The name is used in three precise forms:

MKTD1-framework: the rules of logic of MKTD1 (see Framework).

MKTD1-theory: all statements that can be derived in the MKTD1-framework from the MKTD axioms.

MKTD1-system: the program that checks such derivations: the Kernel in program/newchecker/ and the theorem library in program/types/, written in Standard ML. Synonym: MKTD1-prover.

MKTD2

The second of Obelisk's two formal systems for MKTD. The name is used in three precise forms:

MKTD2-framework: the rules of logic of MKTD2, a classical dependent type theory (see Framework).

MKTD2-theory: all propositions that have a proof term in the MKTD2-framework from the MKTD axioms.

MKTD2-system: the program that checks such proof terms: the Kernel in program/dependent_typechecker.ML and program/dependent_eval.ML, with the library program/verified_theorems.ML. Synonym: MKTD2-prover.

MKTD1 and MKTD2 are never merged. A translation program compares their statements; it does not transfer proofs.

Kernel

The small part of a proof checker that decides whether a proof is correct. All other parts (libraries, search procedures, page generators) can only propose proofs, and the kernel checks them. Obelisk has one kernel for MKTD1 and one for MKTD2.

LCF approach

A design for proof checkers, named after the LCF system of Robin Milner (1972). Theorems are values of an abstract type, and the only functions that create such values are the inference rules. A program can therefore obtain a theorem only by applying rules. The MKTD1 Kernel follows it: the abstract type is called Thm.

Reference: Wikipedia: Logic for Computable Functions.

Derivation

A tree of inference-rule applications whose root is the statement proved. The MKTD1 Kernel keeps the tree of every theorem and can check it again from the start.

Propositions as types

The reading used by MKTD2: a proposition is a type, and a proof of it is a term of that type. For example, a proof of "A implies B" is a function that turns proofs of A into proofs of B.

Reference: Wikipedia: Curry–Howard correspondence.

𝘛, 𝘍, 𝘌, 𝘞

Names of theories that appear inside MKTD1 statements (T, Γ ⊢ φ):

𝘛 is the base theory: a consistent theory whose axioms a program can list. 𝘍 is the theory of the intended model: all sentences true in it. 𝘌 is an unspecified elementary metatheory, used for statements about provability. 𝘞 is a parameter that stands for any theory.

Intended model

The universe of classes that the axioms of MKTD are meant to describe. Obelisk assumes, without proof, that the axioms of 𝘛 are true in it (Foundational assumption).

Foundational assumption

The belief, stated and not proved, that the axioms of 𝘛 are true in the intended model. It implies that 𝘛 and 𝘍 are consistent.

Metalevel

The small number shown in a box before a formula. 0 marks an ordinary statement about classes. Each Quotation and antiquotation raises the number by one: a formula of metalevel 1 speaks about formulas of metalevel 0, for example that a formula is provable.

Quotation and antiquotation

Quotation ‹φ› turns the formula φ into an object that other formulas can speak about. Antiquotation ⟦u⟧ is the inverse step: inside a quotation, it inserts the formula that u stands for. Together they let MKTD1 state facts about its own formulas, such as Holds.

Holds

Holds(T, Γ ⊢ φ) is the formula saying that the statement (T, Γ ⊢ φ) is derivable. It is a formula about a statement, not about classes.

Object-level formula

A formula that speaks only about classes. It contains no Holds, no antiquotation and no other symbol about syntax. Written Fm₀.

Stratification

The kernel rule that class comprehension {x | φ} and definitions accept only object-level formulas φ. Without it one could write a sentence that says of itself "I am not provable" and, together with the reflection rules, derive a contradiction.

Unchecked postulate

A statement that the MKTD1 Kernel accepts through a general definition mechanism that performs no check. It acts as an Axiom. Only a fixed list of names may use the mechanism, and their entries carry the status "Postulated (Unchecked Kernel Schema, Not Derived)" (Status of an entry).

Entry

One numbered item of the Obelisk catalogue: a definition, an axiom, a rule or a theorem. The number has the form section.position, for example 3.65. Every entry has its own page (how to read it).

Status of an entry

What the Kernel knows about an Entry:

Verified: the kernel checked a proof of exactly the stated formula.

Postulated (Kernel Axiom): the statement is an Axiom of the kernel.

Postulated (Unchecked Kernel Schema, Not Derived): an unchecked postulate.

Definitional (Kernel AST): a definition registered in the kernel's definition store, which checks that the definition is well formed.

Primitive / Derived Rule (Kernel): an inference rule of the kernel.

Metatheorem (Holds by the Definition of F, Not a Kernel Rule): true because of how 𝘍 is defined (𝘛, 𝘍, 𝘌, 𝘞); not used by the kernel.

Stated (No Kernel Proof Linked): the statement is written down, and no kernel proof exists yet.

Reading an entry page

The rows of an Entry page, from top to bottom:

Num: the entry number. Title: a short name. Classification: definition, axiom, rule or theorem.

Formula (Unicode), (LaTeX), (ASCII): the same formula in three notations. The boxed number before it is the Metalevel.

Scheme of Types: the same formula with the types of its variables shown. Often it looks the same as the formula.

Axioms Used, Definitions Used: the axioms and definitions on which the kernel proof depends, counted over the whole proof.

Kernel Prf Nodes: the number of steps in the kernel's Derivation, counted without sharing repeated parts.

Proof Term: the first levels of the derivation tree; deeper levels are shown as "...".

Kernel Note: a short explanation of the proof and where it is in the code.

Source Line: where the entry is defined in the source code.

Verification: the Status of an entry.
